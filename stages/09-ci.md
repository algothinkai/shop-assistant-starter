# Stage 9 — retain trustworthy CI evidence

Draft, not approved curriculum. Start in a fresh checkout of
`codex/stage-9-ci-start`; reference `codex/stage-9-ci-reference`. Exact commits are
bound in the algothink manifest. Python3.12+ and Git are required; no packages,
provider account or key are needed. Earlier stage implementations are prerequisites
on this version; the baseline `scripts/test` remains green.

## Choose and predict

CI runs the same checks on a hosted machine without waiting for input. This lab
runs deterministic tests, including authored host envelopes and real local Python
subprocess checks. It does **not** invoke Claude Code or Codex models. Their live
integration remains unverified even after this workflow turns green.

Predict: the review-contract test fails, but quality tests pass. Should the result
say passed because the last command succeeded? No. Preserve all outcomes and fail
the overall report. A missing executable or deadline failure is also not success.

Choose a fixed plan for these four known suites; an adaptive investigation belongs
in a different workflow. Explain why findings from the known defective fictional
code snapshot do not mean the repository itself passed a model review.

## Practice

1. Implement `collect` only in exercises/review_ci/workflow.py. Keep the fixed PLAN:
   foundation, review contracts, host boundaries and quality measurement. Validate
   the Git commit and Boolean dirty-state binding before running anything.
2. Execute every planned suite, recording its actual exit code. Nonzero, invalid
   process outcome or execution failure must fail the overall report; preserve
   later results. Exceptions are redacted; diagnose a failure by running the named
   check locally, not by uploading arbitrary logs or environment data.
3. Run `scripts/verify-review-ci` (four checks), then
   `python3 -m exercises.review_ci.workflow`. The latter writes only
   `.local/ci/review.json`. Its supplied runner starts bounded processes with no
   inherited provider credentials. It removes old evidence before work starts.
4. Add the `review-evidence` job to .github/workflows/review.yml after local checks
   pass. Match the reference job: Python3.12 on ubuntu-24.04, ten-minute job limit,
   run both commands from step3, always upload exactly `.local/ci/review.json`,
   fail when the file is absent, retain seven days. Do not upload the whole `.local`
   directory. Keep read-only contents permission and checkout credentials disabled.
5. On your own remote, push the exact named stage branch or open a pull request;
   inspect the actual job and download its JSON artifact. A local run is not a
   GitHub Actions run. Record job URL, event, checked-out commit and each outcome.
   PR runs may check a merge commit rather than the branch head: compare the artifact
   to that run's checkout evidence, not to an assumed head SHA.

The start installs only the foundation job; it does not hide unfinished stage
checks behind a green stage badge. The reference adds the review-evidence job.
Default push triggers name these two teaching branches; other learner branch names
need an adjusted push filter or a pull request. No schedules, deployment, branch
protection changes, automatic comments or live model workflow are installed.

Expected reference: four runner checks pass; its four-suite report passes
(10 foundation,10 review-contract,12 host-boundary and10 quality tests). Scope
remains OFFLINE_TEST_EXECUTION_ONLY and live_model_review stays UNVERIFIED. Dirty
local work is labeled; a commit hash alone cannot identify uncommitted changes.
Do not claim a dirty report proves that committed source passed.

## Inspect and transfer

Compare a nonzero stage with a simulated unavailable runner in the unit tests.
Both fail without inventing a clean review; later checks still produce evidence.
If the job dies before writing JSON, missing artifact is an error, not a green
cached result. High-level process failures may require rerunning individual checks.

Transfer: a contributor submits a PR that changes tests. Explain why tests from the
contributor are useful evidence but do not independently certify the change. Never
add provider credentials to this untrusted-code job. A future live model workflow
needs separate trusted inputs, explicit authorization/cost bounds and verification;
this fixture workflow cannot establish that Claude loaded CLAUDE.md or used -p.

Hints: (1) validate source binding first; (2) retain one result for each fixed step;
(3) derive overall status from all results, not the final exit code. Ask Claude Code
or Codex to request your prediction, then help only collect or the current workflow
failure; do not copy the complete reference before explaining the failure boundary.

Recovery: save your patch, restore only workflow.py and .github/workflows/review.yml
from the bound start in a separate checkout, then reapply the current checkpoint.
Do not overwrite earlier stage work. Rerun individual checks before pushing again.
Missing Actions access remains unverified; complete local practice meanwhile.
Unread local evidence remains self-reported; Hint/Reveal never grants mastery.
